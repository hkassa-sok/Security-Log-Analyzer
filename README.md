# SSH Authentication Log Analyzer

A student cybersecurity project that analyzes SSH password authentication
logs, flags suspicious patterns, and generates text or JSON reports.

Built with Python's standard library. No external packages are required.

## Features

- Extracts usernames, IPv4/IPv6 source addresses, and timestamps.
- Detects repeated failures within a configurable time window.
- Flags successful logins following repeated failures for the same
  source IP and username.
- Includes log line numbers and timestamps as alert evidence.
- Generates text and JSON reports.
- Includes automated tests and a synthetic scenario evaluation.

Alerts identify activity requiring review; they do not prove compromise.

## Quick Start

Open a terminal in the project folder.

Run the analyzer:

```bash
python3 log_analyzer.py sample_auth.log --threshold 3 --window-seconds 300 --year 2026
```

The report prints to the terminal and saves to `security_report.txt`.

Generate JSON output:

```bash
python3 log_analyzer.py sample_auth.log --format json --output security_report.json
```

Run automated tests:

```bash
python3 -m unittest -v
```

Run the labeled scenario evaluation:

```bash
python3 evaluate.py
```

Evaluation results save to `evaluation_report.txt`.

## Supported Log Format

Example synthetic entry:

```text
Nov 17 10:00:00 lab sshd[100]: Failed password for student from 192.0.2.10 port 50000 ssh2
```

The timed analyzer supports English syslog-style `sshd` messages for:
- Failed password authentication.
- Failed password authentication for an invalid user.
- Accepted password authentication.

The supplied year is applied to timestamps because this log format
does not contain a year.

Sample addresses and usernames are fictional.

## Detection Rules

### Repeated Failures

Generate one alert per source IP when at least the configured number
of failures occurs within the configured time window.

Default:
- Threshold: 3 failures.
- Window: 300 seconds.

The window is inclusive: events exactly 300 seconds apart can qualify.

Failures can involve different usernames from the same source IP.
The first qualifying burst per IP is reported.

### Success After Failures

Flag a successful login when at least the configured number of
preceding failures occurred within the lookback window for the same:
- Source IP.
- Username.

Input events are sorted chronologically. Original line order breaks
ties between events with identical timestamps.

A successful login does not clear preceding failures from the lookback
history, so later successes may also generate alerts.

## Command-Line Options

| Option | Purpose | Default |
|---|---|---|
| `log_file` | Input log path; required | None |
| `--threshold` | Failures needed for an alert | 3 |
| `--window-seconds` | Detection window in seconds | 300 |
| `--year` | Assumed year for timestamps | 2026 |
| `--format` | `text` or `json` | text |
| `--output` | Destination file | Depends on format |

The CLI uses time-window detection.

The Python function `analyze_logs()` also retains an earlier whole-file
counting mode for compatibility with the original tests when its
`window_seconds` argument is omitted.

## Limitations

- Selected password-authentication messages only.
- No public-key authentication analysis.
- No year-rollover or timezone handling.
- Invalid addresses or timestamps are excluded from timed detection.
- Source IP addresses may be shared by multiple users.
- A successful login after failures does not prove compromise.
- No live monitoring or automated response.
- No production environment was assessed.
- Development data is synthetic and limited.
- Large-file performance has not been benchmarked.
- Log authenticity and tampering are not assessed.

## Responsible Use

Analyze only logs you own or are authorized to access.

Do not publish real usernames, sensitive addresses, credentials,
or confidential log data. Review reports and repository contents
before sharing them.
